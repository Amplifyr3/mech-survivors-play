# Pixel art to game mapping (round 5)

Generated by `npx tsx tools/pixel/gamepack.ts` from one table, so this file and the packs never drift. Every row maps a sprite
name the game draws today (`src/render/pixelart.ts`, `src/render/artpack.ts`, `src/render/renderer.ts`, `src/ui/**`, and the
imported packs in `public/art/`) to our frame or animation in `public/pixel/`.

## The one-pass swap

`public/pixel/game/` holds art packs whose frame names already ARE the game's names (`nibbler_move_0`, `art_bulldog_walk_3`,
`crate`, `landing_pad_lit`, …), built from the rows below, plus their emissive masks. The game's own loader reads them unchanged:

```ts
// src/main.ts, after the existing art packs (ours override by name):
if (flags.art) await loadArtPacks(`${import.meta.env.BASE_URL}art/`);
await loadArtPacks(`${import.meta.env.BASE_URL}pixel/game/`);
```

- **Drop-in** rows work with that line alone.
- **Needs code** rows need a small change. Examples: the face paste needs the canopy offsets below; the other pilots and every
  upgrade level need the parts compositor (PIXEL-BIBLE §6b); ours are drawn at native scale, so remove the old `× 3` elite scale.
- **New slot** rows are frames the game has no use for yet, such as crack stages, Popper and Spitter elites, and landmark states.
  They are in `game/` under the listed names, ready for the code that uses them.
- **HD-2D:** `game/index.json` also lists `emissive`: the emissive mask packs (same frame names, see PIXEL-BIBLE §8). The
  landmark light points are in `public/pixel/landmarks1.json` under `lights`, relative to each frame's foot anchor.
- Our sprites are drawn 1 art pixel = 1 logical pixel. Where "size today" differs a lot (the imported v3 art was not always at
  the logical scale), check the renderer's scale factor for that sprite.
